# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev          # Start dev server with Turbopack at localhost:3000
npm run build        # Production build
npm run lint         # Biome linter
npm run format       # Biome formatter (writes changes)
npm run check        # Biome lint + format + import organization (read-only)
npm run test         # Run tests with Vitest
npm run test:watch   # Watch mode tests
npm run test:coverage # Coverage report
```

Database migrations (via Drizzle Kit, for the `portal` database only):

```bash
npx drizzle-kit generate   # Generate a migration from schema changes in db/schema/
```
They are applied on the VM by `make portal-migrate` (infra), which runs the bundled `migrate.js` from the image.

## Architecture

**SIRCA** is an air quality monitoring dashboard (Sistema de Gestión de la Red de Calidad del Aire). On `main` it reads air-quality data from TimescaleDB (`airedb`, owned by `ba-aire/data`) and users from its own `portal` database, both on the VM. It is the only deployment: the old Vercel app (Neon + InfluxDB) and its `vercel` branch were retired in November 2026.

### Dual Database Strategy

- **PostgreSQL, database `portal`** — the app's own data: `user` and `login_attempt`, nothing else. Drizzle ORM (`/db/drizzle.ts`, schemas in `/db/schema/`). Emails are stored lowercase (unique index on `lower(email)`). `user.is_active = false` blocks login. Roles live in `lib/auth/roles.ts`. Equipment/station inventory does NOT belong here: it lives in `dim.*` of `airedb`, declared in `ba-aire/data` (ADR 0013).
- **PostgreSQL, database `airedb`** (TimescaleDB, the regulatory archive owned by `ba-aire/data`) — `/db/airedb.ts`, same `portal` role, **read-only** (V12 in data: SELECT on `bronze`, `silver`, `gold`, `dim`; V17 adds `indice`; V18 adds SELECT on `revision` and EXECUTE on its two write functions; V19 the same for `carga`; V20 adds SELECT on `norma` and EXECUTE on the `reporte` functions; V21 adds `norma.ley_20284`). Plain parameterized SQL via `queryAiredb()`, no Drizzle: the schema is declared by Flyway in `data`, don't duplicate it here. The session is also `default_transaction_read_only` and runs with `jit=off` (the index views add ~1 s of JIT per query otherwise). Never write to bronze/silver/gold: silver and gold are recomputed from bronze. Manual annul/validate decisions go to the append-only `revision` schema, which data's hourly applies (see `/validacion`).
  - `/estaciones` (`lib/location`) reads the latest **raw reading** of each instrument from bronze, every 5 s by SSE. Field names still say `*_mean` (UI shape from the InfluxDB era).
  - `/datos` (`lib/datos`) reads silver (`minute_reading`, `hourly_reading`) and gold (`v_hourly`, `v_moving_8h`, `v_moving_24h`, valid windows only). Same wide-row response as before, plus `<serie>@status` per minute. Intervals: `minute` (one day at a time, with an hour range; capped server-side), `hour`, `mov8h`, `mov24h`. Hourly has four columns per series: `<serie> (validados)` = gold, and the three silver ones `(crudo)` = `value_raw`, `(crudo con alarmas)` = `value_con_alarma`, `(crudo sin alarmas)` = `value`; the moving means only have `(validados)`, and each point is placed at the END of its window. An hour that comes from a manual load (data V19) carries `<serie> (validados)@cargada`; the chart draws it as a hollow point and the table shades it. `lib/datos/series.ts` filters client-side (status checkboxes; validados always on, the three crudos toggled from a select, off by default). No time shifts in the portal: silver's `ts_minute` is the minute START, and the BAM1020 one-hour lag is fixed in data's hourly (V13).
  - `/descargas` (`lib/descargas`) builds the Excel in the browser from one wide row per instant. Hourly: `<p>` = gold.v_hourly (only K minutes), `<p>_raw` = silver `value_raw` (every minute, any status), `<group>_status` (statuses seen, as letters K/A/M/Z/S/C) and `<group>_k_count` (K minutes). Minute: silver `minute_reading`, crudos sheet only. `dv_rumbo` = `dim.rumbo()`, crudos only. The pivot runs in SQL. The hourly query FULL JOINs silver with gold so an hour that exists only as a manual load (V19, no minutes in silver) still comes out; `cargadas` lists the loaded parameters of the hour (not a sheet column, only used to paint, and present in the CSV), their group status gets the letter `H`, and the loaded value is shaded light blue in validados instead of the yellow low-coverage warning. The **validados** sheet is pasted into the network's general spreadsheet: its 18 columns (`lib/descargas/config.ts`, `h2s` always s/d) must not change. Rain (sum of DayRain increments), wind direction (vector mean) and alarm exclusion are computed by data V14, not here.
  - `/ica` (`lib/ica`; `/aqi` redirects to it) reads the air quality index from `gold.v_ica_horario` (data V16/V17). Two indices in the same views, selected by the `indice` column: `EPA` (US AQI, number 0–500+) and `EEA` (European index, category only, `valor` is null). Every query MUST filter `indice`: categories of one and the other don't mean the same. Nothing is computed here (no breakpoints, no NowCast): the portal only reads. Category names and colours come from `indice.v_categoria`, station coordinates, zone and description from `dim.stations`: the station popup on the map shows `station_zone` and `station_description`, both as published by the GCBA; `station_type` (transito/industrial/fondo) is data's own classification, used by the EEA completeness rule, and is NOT shown as if it were official. By default each station shows its latest hour within a 6 h window; the hour picker (`selector-hora.tsx`, like the EEA viewer: slider over the last 48 complete hours, step back, play, step forward) asks for one EXACT hour instead (`hora` = ISO start of the hour, validated in the route: on the hour, with an explicit zone, not in the future), and a station without index at that hour shows "sin índice": it does not fall back to an earlier hour. The city value is the WORST station on screen (`ciudadDe` in the service), not an average. `GET /api/ica?indice=EPA|EEA[&hora=ISO]`; the latest hour is refreshed every 5 min, past hours are cached 5 min in the client (`hooks/useFetchIca.tsx`), and the slider fetches where it is released (250 ms debounce). Layout (modelled on the EEA viewer): under the title, the index buttons and the city card in one row; then the map with the hour picker floating top-right and the colour scale (`leyenda.tsx`: categories, AQI ranges for EPA, "Sin dato", dashed border = incomplete index) bottom-left; on phones both stack above and below the map. There are no station cards: a station's detail (category, hour, pollutants with sub-indices, incomplete-index note, zone, description) is the popup of its marker (`detalle-estacion.tsx`). The map stays mounted across index and hour changes; markers of a previous hour are dimmed until the new one arrives, and nothing of the other index is shown while it loads. The map keeps OSM raster tiles, desaturated.
  - `/validacion` (`lib/revision`) is the manual review of the data: invalidate minutes (a parameter or a whole instrument, `measurement`) or reincorporate alarms, over a minute range `[desde, hasta)` in PUBLISHED time (data V18, schema `revision`, append-only). Everyone with a session sees the list; only an **EDITOR** or **ADMIN** registers or annuls (VIEWER only reads), and every write re-checks role and `is_active` in the `portal` database, not just the cookie. Together with `/cargas`, it is the portal's only write to airedb: `revision.registrar()` / `revision.anular()` (SECURITY DEFINER) inside `transaccionDeEscritura()` (`BEGIN READ WRITE`); the role has no INSERT on any table. Data's hourly applies them on its next run (≤5 min). `/datos` shows those minutes with status `invalidado`.
  - `/cargas` (`lib/carga`) is the manual load of hourly averages ALREADY VALIDATED by an operator (e.g. downloaded from an analyzer after a telemetry outage), into data V19's append-only `carga` schema. The file (.csv or .xlsx, one station, wide: `FECHA`, `HORA`, one column per `parameter_code`; Argentina time, units of `dim.parameters`; empty or `s/d` = no data, not loaded) is parsed IN THE BROWSER by `lib/carga/parser.ts` (all-or-nothing; the user says whether `HORA` marks the start or the end of the hour) and sent as a list of hours. Same permission as `/validacion` (EDITOR or ADMIN, re-checked against the `portal` database). Writes only through `carga.cargar('portal', ...)` / `carga.anular()` in `transaccionDeEscritura()`; a load is annulled whole, never edited. In gold the loaded hour WINS over the measured one and is valid without the 75 % (`gold.v_hourly.is_loaded`); silver is untouched. Capped at `MAX_HORAS` per load: the 10-year history is loaded from the VM console, not here.
  - `/reportes` (`lib/reportes`) is the monthly report per station and pollutant, the PDF published on buenosaires.gob.ar. Everything is computed by data's `reporte.mensual_*` functions (V20, `R__reporte_mensual.sql`; see data `docs/reporte-mensual.md`): daily table, 8 h blocks, hourly max/min, monthly statistics (Excel-compatible percentiles and sample std dev), exceedances against Res. 68/APRA/21 (the stage in force on the first day of the month) and, when the template asks for it, other norms (`p_normas` of `reporte.mensual_excedencias`; `PLANTILLAS[p].normas` in `config.ts`) and the hourly profile by day type (holidays from data's `dim.v_calendario`). The portal only formats: decimals per pollutant, comma decimal, `SD`/`DND`, and `<LD` for ONE-hour values below the analyzer's detection limit (`dim.models.limite_deteccion`). `GET /api/reportes/mensual?estacion&contaminante&mes=AAAA-MM[&formato=json|pdf][&plantilla=clasico|acumar|nuevo]`: JSON (the raw numbers; the screen no longer uses it), or the PDF. `/reportes` is one page driven by a catalog (`lib/reportes/catalogo.ts`): each report is a TYPE (which filters it asks for and how it is built) plus a template. The page first shows only "Plantilla del reporte" (a select grouped by type, each named after its issuer, type and template: "APrA - Plantilla mensual clásica", "APrA - Plantilla mensual nueva v1.5", "ACUMAR - Plantilla mensual clásica"); choosing one loads that type's filter component below (`reportes/components/filtros-mensual.tsx`: month with `components/month-picker.tsx`, station, pollutant, "Vista previa", "Descargar"). Everything lives in the URL (`?reporte=mensual-nuevo&estacion&contaminante&mes`, parsed by `pedidoDe`); switching template within the same type keeps the filters. The server renders the preview under the filters (`reportes/components/vista-previa.tsx`, same sheets as the PDF, CSS of the sheets only). "Descargar" is enabled only while the filters match the preview on screen, fetches the PDF and shows a toast on error. The PDF file name is always `contaminante_estacion_mes_anio.pdf` for the classic template (the name of the files already published: the station without "Parque", accents or spaces, `nox_laboca_septiembre_2026.pdf`) and the same with `_acumar` or `_nuevo` for the other two. An xlsx export was tried and dropped for now: the goal is an Excel identical to the PDF, and exceljs cannot draw charts. A new template of an existing type is one entry in `REPORTES`; a new type (daily, yearly…) also needs its entry in `TIPOS`, its schema in `pedidoDe`, its filter component in `reportes-panel.tsx` and its preview in `page.tsx`. The filters follow the Explorar Datos pattern (centered wrapping row, `bg-secondary` main button). The report itself is an HTML page, `/imprimir/reporte-mensual?estacion&contaminante&mes&plantilla` (`app/imprimir/`, outside `(main)`: no sidebar, and outside the proxy's protected routes), made of fixed A4 sheets (`lib/reportes/html/`: `base.tsx` has the sheet, table and SVG chart components, `clasico.tsx` and `nuevo.tsx` the templates); that page is what gets printed, and it adds `CSS_PAGINA` (html overflow, `@page` A4) on top of the sheets' `CSS_HOJAS`; the embedded preview must not get `CSS_PAGINA`, it would break the portal's scroll. The PDF is printed by Chromium in **Gotenberg** (a separate container; `lib/reportes/impresion.ts`): the API route sends Gotenberg the page URL with a two-minute token signed with `SESSION_SECRET` (audience `imprimir-reporte-mensual`, valid only for that station, pollutant, month and template; it is not a session). The page lets in that token or a portal session, and sends anyone else to `/login`; because the root `loading.tsx` makes Next stream, that redirect is a 200 with a meta refresh, so Gotenberg's `waitForExpression` (`LISTA_PARA_IMPRIMIR`) also waits for a `.hoja` and fails instead of printing the login page. The same expression LOADS the fonts with `document.fonts.load()`: `document.fonts.status` already says `loaded` before a `@font-face` starts downloading, and Chromium printed pages with the text still invisible. To fill dev gold with whole months, data's `make dev-historia` (`db/dev/poblar_historia.sql`). Without `GOTENBERG_URL`/`PORTAL_URL_INTERNA` the PDF answers 503. Three templates with the SAME numbers: `clasico` reproduces the old Excel sheet page by page; `acumar` is the same classic sheets for ACUMAR, whose exceedances also count the Ley 20284 (NOx 1 h > 450 ppb, expressed as NO2; data V21, loaded with that row only), each limit with its own footnote (*1), (*2) and its own line in the chart (the law in red, the Res. 68 NO2 standard in blue); `nuevo` is the redesign (direction "A · Institucional", chosen on a Design canvas on 2026-11-18: summary, exceedances with the month's maximum, daily and hourly-profile charts, method notes). `nuevo` uses Source Sans 3 (OFL, `public/fonts/source-sans-3/`, loaded with `@font-face` from the page, with the basePath; `public/` is what the Dockerfile copies), the classic stays on Arial (Liberation Sans in Gotenberg, same metrics), with the font sizes and row pitch measured on the PDF the spreadsheet exports today (values 8.3 pt, days and column headers 9.2, a row every 9.6 pt; `conTamanos` in `clasico.tsx` applies them over the shared tables, `alturaLinea` in `Tabla` fixes the row pitch). The classic tables follow the sheet: "Percentiles" spanning two rows with 95 and 98 beside it (`tablaEstadisticos(..., percentilesAgrupados)`), thick lines around the header cells (`filasEnCaja` in `Tabla`), between column groups and, with several parameters, between the 8 h blocks and max/min; thin between days and values. The classic has no footer text (the sheet had none), only the page number. The new template's charts use the data's scale: a limit far above the data (more than 1.5× the plotted max) is not drawn but named as out of scale, and a drawn limit says its window and, with several parameters, which one it belongs to. Each has a version tag and a design date in `PLANTILLAS` (`lib/reportes/config.ts`), printed in every page footer of `nuevo` (the classic ones keep it in the config only): bump them whenever that template's layout changes (minor for style, major for content). The `nuevo` band uses the portal colours from the `sirca-design` skill: `--primary` background, `--secondary` line and tag, option "C · Banda sobria" (chosen 2026-11-21 from three mockups): everything left-aligned, the sidebar header block on top (dark BA logo on the `--accent` yellow square plus "APrA / Red de Calidad del Aire"), then the pollutant and, under it, "Estación La Boca · Reporte Mensual · Septiembre 2026", and a single thin turquoise line under the band; yellow only in the logo. The exceedances section names the Res. 68 stage it was checked against. The hourly profile keeps the sheet's row order (23:00 first) and says that hours are labelled by their START. `tests/lib/reportes/fixture.ts` copies the published September 2026 CO sheet of Centenario; `tablas.test.ts` checks the classic tables reproduce it cell by cell. `tests/lib/reportes/septiembre.ts` transcribes the three published September 2026 Centenario PDFs (CO, NOx, PM10) to render both templates with real numbers (`html.test.tsx`).
- **InfluxDB** — gone (it was only used by the retired Vercel app). Locations: `centenario`, `cordoba`, `catalinas`, `cifa`.

### Branches and deployments

- **`main` = production, on the VM** (reachable only through the VPN). The `Dockerfile` builds a standalone image, published to GHCR by `.github/workflows/imagen.yml`. It runs as a quadlet in `ba-aire/infra`, behind caddy, over **plain HTTP** inside the VPN, like the organization's other internal apps (ADR 0017 in infra). Anything that only works with TLS goes through `lib/https.ts`. Images are published ONLY for `vX.Y.Z` tags, not on every merge: a release is `git tag v0.2.0 && git push origin v0.2.0`. Even then nothing deploys by itself: the VM only changes when an infra PR bumps the image digest. Users live in the `portal` database of the TimescaleDB cluster (node-postgres). Pollutant data comes from TimescaleDB (`airedb`).
- There is no other deployment: the `vercel` branch is gone. `vercel.json` stays for now with `git.deploymentEnabled: false`, because the Vercel project is still connected to this repo and without that file Vercel deploys every branch to the internet. Delete it only after the Vercel project is deleted or disconnected.
- Day-to-day work: `feat/*` / `fix/*` branches → PR to `main`.
- `scripts/migrate.ts` is bundled into the image as `migrate.js` to apply `drizzle/` migrations without drizzle-kit. `scripts/create-user.ts` (bundled as `create-user.js`, run by `make portal-user`) creates users, resets passwords and enables/disables accounts from the VM, password via stdin. Never change a database by hand or with `drizzle-kit push`: a fresh database built from `drizzle/` must match the schema. The history restarts at `drizzle/0000_esquema_inicial.sql`; never edit it, add new migrations.

### Layered Data Flow

```
React Hook (useFetchDatos / useFetchDescargas)
  → API Route (/app/api/datos/route.ts, /api/descargas/route.ts)
    → Service Layer (/lib/datos/, /lib/descargas/)
      → Repository Layer (parameterized SQL on airedb via queryAiredb)
```

API routes validate query params with Zod. Services call repositories; request values always travel as `$n` parameters, never interpolated.

### Authentication

- JWT sessions via `jose`, stored in httpOnly cookies, 7-hour expiration.
- `/lib/auth-session.ts` — server-only session management (`verifySession()` redirects unauthenticated users).
- Passwords hashed with `bcryptjs`.
- Protected routes live under `/app/(main)/` and use a shared authenticated layout.

### Routing Structure

- `/app/(main)/` — protected routes (ica, datos, descargas, estaciones, reportes, validacion, cargas)
- `/app/api/` — API route handlers
- `/app/admin/` — admin login
- `/app/login/` — user login

### UI Stack

- **shadcn/ui** (New York style) on top of Radix UI primitives — components in `/components/ui/`
- **Tailwind CSS v4** for styling
- **Chart.js / Recharts** for pollutant data charts
- **Mapbox GL / MapLibre GL** for station maps
- Data tables (`/datos`, `/descargas`) are plain `<table>` elements, no table library, styled with the classes in `components/tabla-datos.ts` (brand-blue header, zebra rows, comma decimals)
- Every page title is `components/page-header.tsx` (one `h1`, the description as a paragraph; `centrado` on filter pages). An empty result is `components/sin-datos.tsx` (blue text, never yellow: it fails contrast)
- Sidebar items are real links (`next/link`), reachable with Tab and openable in a new tab. The user avatar is built locally from the initials: no external avatar service (it would receive every user's email)
- Calendars default to Spanish (`react-day-picker/locale` `es`)
- **Sonner** for toast notifications
- **Lucide React** for icons

### Path Alias

`@/*` maps to the repo root (configured in `tsconfig.json`).

## Environment Variables

```
DATABASE_URL=         # PostgreSQL connection string (VM: base `portal`)
AIREDB_URL=           # Same role `portal`, database `airedb` (read-only). Local: scripts/dev-db.sh prints both
SESSION_SECRET=       # Base64 key for JWT signing
PORTAL_HTTPS=         # "true" only if served behind TLS: re-enables the secure cookie and CSP upgrade-insecure-requests (lib/https.ts). Default: plain HTTP inside the VPN
GOTENBERG_URL=        # Gotenberg, which prints the monthly report PDF. Local: docker run --rm -p 127.0.0.1:3001:3000 gotenberg/gotenberg:8 → http://localhost:3001
PORTAL_URL_INTERNA=   # How Gotenberg reaches the portal, WITHOUT the basePath. Local: http://host.docker.internal:3000
```
